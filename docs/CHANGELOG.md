# 更新日志

> 版本格式：Semantic Versioning（主版本.次版本.修订）

## 0.9.5 (2026-09-03)

### 🔧 变更

- 删除依赖小样本校准资料的文档平行性门控，新增固定 60 秒原子对齐时限；时限不包含原始
  embedding 编码，也不包含后续合并候选编码。
- 简化 GUI 与报告概念，只展示准备、原子对齐、组合处理和总处理等用户可理解的耗时；不再
  暴露校准身份、工作量代理或求解器内部状态。
- 为相似度矩阵保留内部容量保护，超限时直接提示输入规模过大，不提供额外配置或延长重试。
- 优化文本对表格复制格式，将当前评分纳入表格；修复重置修复操作后当前评分未刷新的问题。
- 删除旧校准资源、校准 benchmark 与过时评估脚本，并统一使用 Black 格式化 Python 代码。

## 0.9.4 (2026-08-28)

### ✨ 新功能

- 建立以审校区为原子单位的 AI 责任编辑工作流，支持调阅和调整相邻上下文、工具化结构编辑、
  可取消执行与独立回归语料。
- 统一跨关系编辑、手动校订、文本搜索、文件对状态列表和固化差异审查。

### 🔧 变更

- 余弦观测统一量化为 binary16；组合分歧增加硬拆分边界 `ΣΔi > 0` 证据门控，
  在有直接局部证据时消解 gap/merge 分歧。
- 修复来源、操作和人工认可的分层语义；重对齐与固化使用统一关系身份协调器，
  只复用仍然有效的工作状态。
- 非 `1:1`、语言杂糅和低分诊断在对齐时写入报告并冻结；配置变更只影响下次重对齐。
- 长时任务改为响应式模态进度窗口，文字使用 Qt/系统原生调色板。

## 0.9.3 (2026-08-26)

### 🔧 变更

- 工作报告的同目录原子替换在 Windows 遇到短暂读取句柄时执行有限退避重试，避免管理器、

  `cache_revision` 的 0.9.2/0.9.3 报告。词向量缓存键仍只由编码语义身份与文本决定。

## 0.9.2 (2026-08-26)

### 🔧 变更

- 顺序门控以无序最优证据 `U` 与单调最优证据 `M` 的相对损失取代 mutual-nearest 链外
  计数，并让 `M` 统一提供可跨越软脚手架；门控工作流收敛为通过/拒绝，具体原因仅作诊断。
- 顺序校准由 beta-binomial 计数改为困难正例损失的 conformal 上尾分布；此前因重复拟声词
  被误拒绝的 `167807` 现在产生可消费的 `needs_review` 路径。
- CLI 报告管线的自动拆分现在复用全局词向量缓存，避免局部重对齐绕过缓存重复编码。

### ⚡ 性能

- 合并统计门控、中心候选和双组合模型中的重复计算，并批量计算双向保守秩；292 份真实
  缓存命中文档的 MDL 求解总时减少 36.2%，主路径、备选路径与状态逐份不变。
- 新增可复现的 MDL/legacy 真实文档运行时间脚本，输出路径摘要以检查性能优化的语义等价性。
- 将有限整数秩直接映射到预计算 rank-code 码本，避免对全文格点重复计算相同的对数码长。
- 利用 Pareto 支配在任意共同后缀下保持的性质，由一次前向 DP 同时产生语义前沿和回溯
  路径，删除第二套 exact-complexity 生产递推；292 份真实文档的双路径与状态保持不变。
- 清理已落地或被替代的阶段性设计稿、旧界面截图和未使用维护脚本，将长期有效的研究与
  迁移结论收敛到一份归档，并修正文档导航、构建命令与版本说明。

## 0.9.0 (2026-08-24)

### 🔧 变更

- 默认对齐算法迁移为统计门控稀疏 MDL；拒绝与组合分歧成为报告中的显式状态，不再静默回退 legacy 锚点算法。
- 收敛求解器提升到正式 `dualign.algorithms.mdl` 包；未采用的上下文残差实现已删除，实验方法、数据和反例保留在研究文档中。
- `legacy-anchor-v1` 冻结为 CLI 显式 benchmark；GUI 移除锚点密度/gap 质量门控配置，只保留不影响路径的异常显示参数。
- 拆分后的固定分区与 legacy 全文回退改为无 gap 局部递归 MDL；拆分只引入边界，随后允许另一侧重新合并。
- 将 `report.json` 确立为唯一对齐与校订工作状态，记录中性文档 A/B、块级关系、正文哈希与非敏感生成来源。
- GUI 普通保存只更新报告；“固化修改”可分别选择文档 A/B 的合并、拆分和校订，并以可恢复的三文件事务写入正文和重建后的报告。
- 新增 `dualign solidify` 预览/应用命令、JSON/TOML 配置、五种预设以及部分固化后的剩余操作重锚。
- 固化策略加入双侧“删除文本对”；占位保持为报告操作。双侧 N:M 合并/拆分改为原子固化，审核标记在当前报告或固化历史中保留。
- 新增 GUI 与 `dualign solidify-batch` 批量固化入口；固化后按关系状态迁移待处理 AI 建议和评分，并归并旧版追加式修复日志中的冲突决定。
- 固化后对未来正文重新运行正式对齐，不再继承编辑阶段的复合关系；仅按双侧文本完全相同且唯一的关系迁移未固化操作、待处理 AI 建议和评分。
- `align_documents(reset_work_state=True)` 可复用有效对齐关系并重建干净工作报告，避免重新对齐时误带旧 `flag`、审核和评分状态。
- CLI `align` 与 Python `align_documents()` 只生成报告，不再隐式导出等行 Markdown。
- 正文校订不再要求两侧行数相等，GUI 与公共参数逐步统一为文档 A/B 术语。
- 删除旧报告迁移、`repaired/`、`.bak`、晋升和 YAML 双状态支持。
- 将按章节分散的 `vecs.db` 合并为全局行级嵌入缓存，真正支持跨文档复用。
- 缓存写入改为不可变键语义，增加 SQLite 忙等待和大批量查询分片。
- 新增 `scripts/migrate_embedding_cache.py`，支持幂等迁移、逐库校验及安全移除旧分库。
- Ollama 嵌入批次默认限制为 128 条；tokenizer 拒绝批次时自动二分重试，并保留服务端错误详情。
- `[F]` 改为独立的待复核状态：正文校订不再自动清除，只有显式通过或取消标记才解除；正文变化会使旧通过状态失效。
- 修复稳定关系身份迁移后撤销 AI 建议时把 ID 元组误作序号的异常；非连续多选的跨关系合并/校订统一禁用，避免破坏单调顺序。
- 清除 PyInstaller 中已移除 `snap_state` 的隐式导入，并避免 Windows 路径在生成 spec 时产生转义警告。

## 0.7.0 (2026-06-xx)

### ✨ 新功能

- **跨 snap 校订**：AI Agent 支持 `edit` 连续 snap 范围（如 `snap_range="10-13"`）
- **嵌入指令（Instruction）机制**：编码时自动添加双语平行对齐任务描述，显著提升语义区分度
- **质量门控 G1/G2/G3**：真锚点密度、孤行占比、合并触顶三级质量评估
- **ProviderManager**：模型提供方管理，支持 Ollama / LM Studio / 自定义 API 切换

### 🔧 变更

- **重构对齐引擎**：Phase 1→5 流水线，从递归锚点 + 赝锚点 + 全局枚举合并 + 单次 DP 最终决选
    - 真锚点搜索改为递归迭代（分段后对手减少 → 被遮挡锚点浮现）
    - 移除 restricted/full DP 双轨，合并为单一 DP
    - 移除 pure/mixed/adjacent 间隙类型划分
- **AI Agent 重构**：移除 auto*note/would*\* 暴露给 AI，改为两层文本模型
- **嵌入缓存从 NPZ 迁移到 SQLite**：支持行级缓存，跨文档共享
- **Ollama AI 审校后端移除**：仅嵌入服务使用 Ollama，AI 审校统一使用 DeepSeek API
- **CollapsibleSection 回退为 QGroupBox**：消除 Windows DWM 启动闪烁
- **SnapState 三层模型**：原始事实 / 当前状态 / 处理历史

### 🐛 修复

- GUI 启动闪烁（root cause: CollapsibleSection HWND）
- 多个索引漂移问题（不可变快照 + append-only log 根治）
- ScoreManager worker invokeMethod 崩溃

### 💥 破坏性变更

- `RepairAction.data` 中 `source` 字段移入顶层（`action.source`）
- `ChapterContext` 移除 `op_statuses`、`src_out`、`tgt_out`
- 移除 `OllamaSimulatedBackend`（AI 审校不再支持 Ollama 后端）
- `report.json` 中 `ops` 字段使用 `{"s": [...], "t": [...], "sc": ...}` 格式
- 缓存目录结构调整（迁移到 SQLite `vecs.db`）
