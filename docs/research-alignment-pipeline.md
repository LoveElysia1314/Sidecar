# 限时稀疏 MDL：设计与验证

> 状态：`mdl-v1` 已作为生产默认。本文解释当前约束为何从“判断文档平行性”收敛为
> “限制原子求解时间”。面向使用者的简明说明见[对齐算法](algorithm.md)。

## 1. 问题重新定义

生产门控真正需要避免的损失只有两类：错误拒绝可用输入，以及让异常输入长期占用计算资源。
前者无法由当前规模的校准集可靠控制；后者可以直接测量。因此当前实现不再预测文档是否
平行，也不再把 embedding 校准身份作为运行前提，而是直接尝试对齐并限制昂贵阶段的时间。

固定时限还有一个工程优势：它约束实际墙钟负担，能覆盖脚手架稀疏、候选前沿膨胀、行数失配
和内容完全替换等不同退化方式。此前使用窗口几何估算工作量，无法反映全局 Pareto 前沿规模；
实测中甚至出现估算值低于正常文档、实际求解却超过一分钟的案例，因此该代理已删除。

## 2. 计时边界

一次运行分为三段：

```text
原始 embedding 获取
        ↓
准备：相似度、排名证据、单调脚手架
        ↓
原子对齐（固定 60 秒）
  ├─ 局部候选搜索
  ├─ 全局路径求解
  └─ 结构编码计算
        ↓
组合处理：合并文本编码、双模型比较、边界复核
```

60 秒只覆盖“原子对齐”。它不包含任何原始文本编码，也不包含后续合并候选编码。这样记录的
时间可以直接回答求解器本身消耗多少，而不会把本地模型、远程 API、缓存命中或批大小差异
混进同一个数。

默认值固定为 60 秒，用于兼容较低算力机器。产品不提供配置项和“以更长时限重试”，避免为
小概率异常增加界面、配置与报告状态。

## 3. 停止机制

截止时间通过运行上下文传入局部 DP、结构计数和全局候选前沿。循环在稳定边界周期性检查，
超时后抛出统一的内部异常，由管线转换为：

```text
status = rejected
reason = alignment_timeout
```

报告保存实际原子耗时、固定时限和停止阶段。GUI 只显示“对齐计算超过 60 秒，已停止”，不展示
内部阶段名、状态数或开发时使用的工作量概念。

## 4. 输入容量保护

时间限制无法保护原子求解之前的 `n×m` 相似度矩阵。正式入口因此保留固定矩阵单元上限，
在明显超出内存与基础计算能力时返回 `input_too_large`。这是内部产品容量，不是平行性判据，
也不作为用户配置。

单行 token 数仍受 embedding 提供方的输入能力约束。界面应把提供方错误转换为普通输入提示，
而不是展示模型上下文长度、批次实现或其他开发者参数。

## 5. 压力验证结论

2026-09-02 使用轻小说资源中最长的实测文档对（两侧各 2511 行）进行三种破坏：随机打乱一侧、
随机删除一侧一半行、以其他文档替换一侧。正常原子对齐约 0.8 秒；三种异常都进入长时间全局
搜索，其中打乱超过 240 秒仍未完成，另外两种超过 60 秒仍未完成。局部窗口生成均少于约
0.31 秒，瓶颈位于全局前沿与结构求解。

这组压力测试曾导致整机宕机重启，因此不再用无限时实跑作为常规回归。自动测试通过把固定
时限临时设为零验证停止契约，并对正常小矩阵验证各段耗时字段。真实长文档只在受控环境下
做低频性能复验。

## 6. 后续工作

- 继续优化全局前沿的内存峰值和截止检查粒度，但不改变 MDL 目标；
- 建立安全、可中断的合成压力基准，记录进程内存与实际停止延迟；
- 若未来需要平行性诊断，另建足量且文档隔离的 benchmark，冻结评价标准后独立验证；
- 保持 GUI、配置和正式报告只呈现用户需要作决定的信息。
