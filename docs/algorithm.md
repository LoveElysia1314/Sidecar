# 对齐算法：限时稀疏 MDL

> 当前生产默认：`mdl-v1`。旧锚点算法只可通过 CLI 的
> `--algorithm legacy-anchor-v1` 显式运行，用于回归和 benchmark；新算法停止时不会
> 静默回退旧算法。

## 1. 输出范围

Dualign 为两个自然分段文档生成单调、完整覆盖的：

```text
1:1 / N:1 / 1:N / 1:0 / 0:1
```

一般 `N:M`、交叉关系和块置换不在当前生成语法中。算法可能返回：

- `aligned`：两个组合证据模型给出同一路径；
- `needs_review`：组合证据在局部产生分歧，仍提供可审阅的暂定路径；
- `rejected`：输入为空、规模超过安全处理范围，或原子对齐超过 60 秒。

这些状态不声明文档“有多平行”。Dualign 负责在产品能力范围内尝试对齐，并把不确定关系
交给审核，而不是用小样本校准资料替用户判断输入内容。

## 2. 证据与软脚手架

原始文本分别编码一次，归一化后计算余弦矩阵。每个矩阵格点的语义证据取双向保守排名节省：

```text
e(i,j) = min(row_rank_saving(i,j), column_rank_saving(i,j))
```

它对严格单调分数变换不变，没有跨模型固定余弦阈值。在全部正证据上求最大权单调链，形成
软脚手架。脚手架只用于定位候选窗口，任何点都可以被正式路径跨越，不是强制锚点。

## 3. 原子候选与全局求解

每个中心窗口运行完整覆盖的局部 Pareto MDL，产生 `1:1 / N:1 / 1:N` 原子候选。正式全局
求解器把这些候选与 gap 路径放在同一单调图中，依据语义编码长度和结构编码长度选择完整
覆盖路径。它不使用 merge penalty、gap penalty、锚点密度或按案例调整的相似度阈值。

原子对齐阶段包含：

1. 中心窗口内的候选搜索；
2. 原子候选的全局路径求解；
3. 与该求解直接相关的结构编码计算。

该阶段固定最多运行 60 秒。计时不包含原始文本 embedding 编码，也不包含之后为组合候选
执行的 embedding 编码。时限是产品运行边界，不是平行性门控，也不提供用户配置或延长重试。

实现使用协作式截止检查，在局部 DP 和全局前沿循环的安全位置停止。因而实际停止时间可能
略高于 60 秒，但不会为了检查时限而改变目标函数或候选顺序。

## 4. 组合证据与复核

原子路径确定后，算法再对相邻原子关系构造两个可解释的组合证据模型：

- 先验模型：独立结构选择；
- 后验模型：共享同一可观测语义编码。

两者一致时输出 `aligned`；不一致时输出 `needs_review`，保存暂定路径、备选路径和最小分歧区。
仅对特定 `2:1 / 1:2` 分歧，算法可重新编码真实前后缀，使用直接边界证据消解歧义。

组合文本编码及上述复核处理不计入 60 秒原子对齐时限，但会单独记录耗时，便于区分模型服务
延迟与路径求解耗时。

## 5. 安全边界与耗时统计

全文相似度矩阵需要 `O(nm)` 内存和计算。程序因此保留一个内部矩阵容量上限，在分配或搜索
之前拒绝明显超出产品能力的输入。它不是面向用户的调节项，也不表达输入质量。

报告和 GUI 使用以下简单时间概念：

- 准备：余弦、排名证据和软脚手架；
- 原子对齐：受 60 秒限制的候选搜索与全局求解；
- 组合处理：组合候选编码、双模型比较和边界复核；
- 总处理：上述程序处理时间之和，不含最初 embedding 获取。

更细的局部候选与全局求解耗时保留在报告统计中，主要用于性能诊断，不作为用户决策概念。

## 6. 能力边界

- 一般乱序和块置换不属于单调行对齐，应先由更高层恢复顺序；
- 当前生成语法不包含一般 `N:M`；
- OCR 乱码、缺行、错章节和语言混杂属于输入质量问题；
- `aligned` 不等于逐行置信度保证，embedding 与候选覆盖仍会影响结果；
- 超时只表示本次求解未在产品时限内完成，不表示文档不平行。

如果未来确实需要平行性置信度，应建立独立、足量、覆盖目标语言和领域的 benchmark，并把
它作为诊断能力研究；不应再次与计算安全或产品状态混为同一个门控。

## 7. 为什么收敛为时间边界

旧门控试图在运行前回答“这两份文档是否足够平行”。这个问题依赖语言、领域、分段方式和
embedding 模型，少量校准样本无法给出稳定答案；新注册模型还会因为没有配套资料而被拒绝。
相比之下，产品真正必须控制的是异常输入占用多少资源，这可以直接用墙钟时间和矩阵容量衡量。

固定时限还能同时覆盖脚手架稀疏、候选前沿膨胀、行数失配和内容完全替换等不同退化方式。
早期尝试过用窗口几何预测工作量，但该代理无法反映全局 Pareto 前沿规模，已从生产流程删除。
因此当前选择是：不在前置阶段猜测内容质量，直接运行同一求解器，并在昂贵阶段达到边界时停止。

## 8. 压力验证与维护

2026-09-02 曾以两侧各 2511 行的长文档进行破坏性压力测试：随机打乱一侧、随机删除一侧一半
行，以及用其他文档替换一侧。正常样本的原子对齐约 0.8 秒；异常样本的局部候选生成仍低于
约 0.31 秒，但全局前沿搜索持续超过 60 秒，打乱样本在当时的无界运行中超过 240 秒仍未完成。
瓶颈由此被定位到全局路径与结构求解，而非 embedding 或局部窗口。

无界压力测试曾导致整机宕机重启，因此不作为日常回归。自动测试以可控的极短时限验证停止
契约，并用正常小矩阵验证各段耗时字段；真实长文档只在隔离、可中断的环境中低频复验。
