# 对齐算法：统计门控稀疏 MDL

> 当前生产默认：`mdl-v1`。旧锚点算法只可通过 CLI 的
> `--algorithm legacy-anchor-v1` 显式运行，用于回归和 benchmark；新算法拒绝时绝不
> 静默回退。

## 1. 问题与输出

输入是两份保持原顺序的非空 Markdown 行序列及同一嵌入模型产生的向量。输出是在单调、
完整覆盖约束下由下列关系组成的路径：

```text
1:1 / N:1 / 1:N / 1:0 / 0:1
```

一般 `N:M`、交叉关系和块置换不在当前语法中。算法可能返回：

- `aligned`：两个组合证据模型给出同一路径；
- `needs_review`：文档适合单调对齐，但组合证据在局部产生分歧；
- `rejected`：文档缺少足够的对应证据、顺序与单调模型不相容，或没有
  与当前 embedding 身份匹配的校准资料。

`needs_review` 仍保存 provisional 路径和替代路径；`rejected` 不生成伪对齐，也不调用
旧算法补结果。

## 2. 原子语义证据

归一化向量后计算全文余弦矩阵。每个格点分别在其行和列内排名，用有限 Zipf 码表示
“相对均匀选择节省了多少 bit”，并取双向较弱证据：

```text
e(i,j) = min(row_rank_saving(i,j), column_rank_saving(i,j))
```

它对严格单调分数变换不变，没有固定余弦门槛。但 rank 只能回答“哪个更像”，不能回答
“是否存在真正对应”，因此文档适用性必须由独立统计门控判断。

## 3. 统计适用性门控

门控与路径目标分离，只有一个产品政策量 `alpha`。当前校准资料与 embedding 模型、
instruction、语言对和领域绑定。

1. **存在性检验**：用双向最近邻余弦均值作为统计量，与真实非对应文档对构成的 null
   比较，计算 conformal 上尾 p 值；证据不足时拒绝。
1. **顺序相容性检验**：在全部正 rank-code 证据上分别求不限制顺序的最大权一对一匹配
   `U`，以及保持双侧严格递增的最大权一对一匹配 `M`。相对单调损失
   `(U-M)/U` 与经审阅仍可产生可用单调路径的文档分布作 conformal 上尾检验；损失显著
   过大时拒绝。`U=0` 时顺序检验没有拒绝证据，由存在性检验决定是否继续。

这里没有锚点密度、最大锚点间隙、merge penalty 或 gap penalty。GUI 的低分异常参数只
控制对齐完成后的显示标记，不参与门控。

当前随包校准仍来自有限探索集，只能支持已测 embedding/领域内的保守使用，不能解释成
跨语言、跨领域的普遍错误率保证。缺少匹配校准时，算法明确拒绝。

## 4. 可跨越脚手架与候选图

顺序门控得到的 `M` 匹配链直接用于定位计算窗口，不是不可跨越锚点。对每个内部脚手架点建立
`[前一脚手架点, 后一脚手架点]` 中心窗口；每个脚手架点至少在一个窗口内部，因此错误
脚手架不会成为不可跨越边界。

每个窗口运行任意连续 `N:1/1:N` 的局部 MDL，并提交各非支配复杂度的最佳路径支持边。
所有候选边进入同一个稀疏全局求解器。该单覆盖构造取代了两遍奇偶交错，没有 parity、
固定窗宽、固定每窗路径数或语义剪枝阈值。脚手架变稀时窗口自然扩大，逐渐趋向完整
MDL。

## 5. 结构码与精确求解

结构复杂度定义为：

```text
1:1 = 0
N:1 / 1:N = N - 1
每条 gap 行 = 1
```

结构码由完整语法中同复杂度脚本数和 Elias-delta 码给出，目标为：

```text
semantic_bits - structure_bits
```

给定路径关系数 `r`，复杂度恒为 `n + m - 2r`。因此 gap 网格的具体走法不携带额外
信息，可以精确取商为稀疏语义边上的固定关系数最大权单调链。该变换不近似结果，也不
需要枚举二维 gap 路径。

## 6. 组合证据

原子覆盖能表达“各行都与目标相关”，却不能证明拼接后构成同一翻译命题。算法只对可能
验证或翻转原子路径的复合边编码完整块及直接竞争子块，并保留两个可解释的反事实码：

- `P`：在原子对应分布上按 leave-one-out 完整块增益秩作归一化后验重加权；
- `D`：最佳直接子块 bits 加被删行必要性秩节省，形成反事实描述长度差。

二者均在有限 rank null 中换算为 bit，能与原子 bits 比较，不把余弦差乘经验常数。
两条路径一致时自动接受；分歧时保留 `D` provisional 路径、`P` 替代路径及最小分歧岛，
交给人工复核。原子路径 `A` 仅作为未组合验证的诊断基线，不参与是否产生分歧标记：
状态规则严格为 `D = P` 时 aligned、`D != P` 时 needs_review。

## 7. 拆分后的局部重对齐

人工或自动拆分只负责在一侧引入硬边界，随后双侧共同进入局部递归对齐。例如原 `3:1`
在右侧拆成两句后形成 `3:2`，路径 `2:1 + 1:1` 合法，最终可展平为两行。

局部语法只允许 `1:1 / N:1 / 1:N`，不含 gap 和一般 `N:M`。DLD 与 posterior 先决定
复杂度，完整拼接证据在该复杂度内选择边界；复杂度分歧或完整路径精确并列时保留父关系
并标记“拆分需复核”。旧固定分区和旧全文锚点回退均已退出该路径。

## 8. 复杂度和实际性能

全文余弦矩阵仍需 `O(nm)` 内存和 `O(nmd)` 点积计算。顺序比较增加一个矩形最大权匹配
和一个向量化加权 LCS；后者为精确回溯保留 `O(nm)` 表。高平行文档的中心窗口访问量接近
线性；相关但低脚手架密度的长文档可退化到完整二维 MDL。完全非平行文档通常在局部
MDL 前被统计门控拒绝，但拒绝本身仍须支付全文余弦和排名成本。

在 292 个含旧生产异常、向量和组合文本缓存命中的真实文档上，2026-08-25 的等价实现
优化把求解总时从 48.12 秒降至 30.69 秒，中位从 0.119 秒降至 0.080 秒、P95 从
0.422 秒降至 0.250 秒；292 份主路径、备选路径和状态逐份相同。同机单次回放冻结的
`legacy-anchor-v1` 为 88.29 秒、中位 0.152 秒，但短文档仍可能由旧算法更快完成，因此
不能据此声称每份文档等速。局部拆分通过生产服务入口回放 174 个父关系，134 个可拆
关系总耗时约 0.374 秒，其余 40 个因硬拆分没有新增边界而按契约拒绝。

后续等价化简又将 rank bits 改为有限码本查表，并由同一次 Pareto DP 同时产生语义前沿
和回溯路径；它们不增加算法参数。最长真实文档的五组交替回放中位数约从 0.940 秒降至
0.825 秒，292 份路径与状态不变。完整集合单次求解会随系统负载在约 25--31 秒间波动，
不宜把一次 wall-clock 差值解释为精确加速率。

2026-08-26 将 mutual-nearest 链外计数替换为 `U/M` 单调证据损失，并由 `M` 统一提供软
脚手架。292 份真实异常清单回放的主路径、备选路径和状态逐份不变；优化后的单次求解
约 `34.9 s`、中位 `0.089 s`、P95 `0.316 s`。该模型比历史同机 `20.5 s` 求解基线更贵，
主要成本来自精确无序匹配；但它删除了 `argmax → mutual → 链外计数 → beta-binomial`
这一脆弱投影，并修复了重复拟声词长文档的错误拒绝。性能差值会受系统负载影响，不解释
成严格倍数。

## 9. 能力边界

以下情况不应通过新增阈值或案例例外逐个修补：

- 一般乱序、交叉翻译或块置换；它们需要独立的块匹配/置换层；
- 一般 `N:M`、真实漏译/增译与边界位于 hard splitter 片段内部；
- embedding 无法区分的短应答、重复句、专名、否定、数值或说话人归属；
- 同主题译注、相关正文和自然段续行造成的组合语义混淆；
- OCR 乱码、缺行、错章节和语言混杂等数据质量问题；
- 与校准域不同的语言、体裁、embedding 或 instruction；
- 统计门控通过但个别关系仍错误——门控是文档级适用性判断，不是逐行置信度。

机器表示下严格多解时应复核；超出语法时应明确拒绝或交由更高层处理。新增算法能力应
来自新增信息（如经独立数据校准的 token 覆盖或跨编码器似然），而不是恢复固定阈值。
