# 局部拆分递归对齐研究

## 当前结论

用户澄清后，局部拆分不再被建模为“保持参考侧完全不动，把拆出的片段强制分成
固定数量的组”。更准确的模型是：

1. 父关系已经指出两段局部文本互相对应；
2. 在较少行的一侧执行一次保守硬拆分，引入新的可用边界；
3. 把原有另一侧各行和拆出的片段共同放回一个局部、单调、完整覆盖的对齐问题；
4. 局部路径允许 `1:1 / N:1 / 1:N`，但不允许 gap 和一般 `N:M`；
5. 每条局部关系的两侧分别拼接成一行，作为 split 操作的最终输出。

所以原关系为 `3:1`、右侧硬拆成两句时，局部问题是 `3:2`。路径
`2:1 + 1:1` 完整合法，摊平后得到两个双边非空的输出行，也就是用户所说的
`2:2`。这里“拆分”只描述引入边界的动作，不意味着随后禁止另一侧合并。

正式求解器位于 `src/dualign/algorithms/mdl/local_recursive_mdl.py`，生产适配层位于
`src/dualign/services/local_realign.py`，已经接入 `RepairService.try_split`。当前迁移使用
下文“按复杂度条件化的完整路径选择”：DLD 与 posterior 决定复杂度，完整拼接证据在
该复杂度内选择边界；复杂度分歧或完整路径精确并列时保留父关系并标记复核。旧固定
分区与 legacy 全文回退已经退出拆分路径。

## 条件化问题与结构码

设硬拆分后的局部矩形为 `n×m`。候选边是所有连续、双边非空，并满足一侧长度为 1
的矩形边：

```text
1:1 / N:1 / 1:N
```

候选生成器只删除不可能位于任何完整路径上的边：除起点和终点外，边的前后都必须
给两侧至少留下一个元素。对 `1×1` 到 `5×5` 的全部矩形，已经用独立递归枚举器核对：

- 剪枝后的边集合，恰好等于至少属于一条完整合法路径的边集合；
- 按复杂度统计的路径数完全一致；
- 没有 gap、一般 `N:M` 或遗漏的合法边。

原先把它沿用为全文 MDL 的“先编码复杂度、再编码同复杂度脚本”会重复惩罚合并。
局部问题已经以“父关系成立且用户明确执行拆分”为条件；此时完整脚本才是同一层级的
互斥假设。当前原型对所有完整合法脚本使用均匀枚举码：

```text
L(path | parent correspondence, explicit split) = log2 |P(n,m)|
```

它对同一个局部问题中的所有路径为常数，因此没有 merge penalty、gap penalty、跨度
上限或手调复杂度权重。合成 `3×3` 案例已验证，这个条件码能够选择
`1:2 + 2:1`；旧的通用复杂度码会因额外 4 bit 结构费用而无条件偏向三个 `1:1`。

这里的“均匀”不是声称所有结构在自然语言中先验同概率，而是避免在没有局部结构
校准集时偷偷引入形状偏好。将来若有标注充分的局部语料，可以替换为经过校准的结构
分布；不能从当前 174 个旧算法产出的关系反推惩罚常数。

## 语义证据与门控

原型对同一无 gap 候选图运行三种可解释的语义视图：

1. **反事实描述长度差（DLD）**：比较完整拼接块和直接前/后子块，组合增益经同侧
   对手中的有限 rank 转成 bit；
2. **后验重加权**：原子 mutual-rank bit 定义基础对应分布，leave-one-out 组合增益
   的 Zipf rank 作为归一化 change of measure；
3. **完整拼接余弦路径**：只在前两者选中的同一复杂度内作路径审计，不把余弦差乘
   常数后加到 rank bit 中。

DLD 和后验修正满足归一化的编码解释，没有余弦阈值或自由缩放系数。完整拼接余弦与
bit 不可直接相加，所以它只比较路径签名。

早期隔离实验使用的保守门控为：

```text
DLD 与 posterior 的复杂度相同
and DLD 路径 == posterior 路径 == 同复杂度 raw-composition 路径
    -> aligned
否则
    -> needs_review，保留父关系
```

这是参数为零的模型分歧门控，不是“分差超过某阈值”。但三种视图并非三个统计独立的
投票者：DLD 与 posterior 共享原子证据，完整拼接又使用同一 embedding。因而一致只
能解释为“已检查的反事实没有改变决策”，不能解释为经过校准的错误概率。

## 当前生产全流程

```text
父 N:1 / 1:N 关系
  -> 对少行侧逐行执行保守 hard_split
  -> 若没有新增边界：unsplittable，保留父关系
  -> 构造双边非空的局部 n×m 问题
  -> 生成全部结构上 live 的 1:1 / N:1 / 1:N 边
  -> 编码原子行、完整块及 leave-one-out 直接竞争块（批量并缓存）
  -> DLD、posterior、raw-composition 各自做精确无 gap DP
  -> DLD 与 posterior 复杂度一致：由同复杂度 raw-composition 路径选边界
  -> 逐关系拼接两侧文本，生成 split
  -> 复杂度分歧或 raw-composition 精确并列：needs_review，原关系不变
```

无 gap 是语法不变量，而不是跑完全文对齐后再检查索引覆盖。索引覆盖只能证明每个输入
出现过，不能阻止输出 `1:0 / 0:1`。

## 与当前生产回退的比较

迁移前的 `RepairService.try_split` 先运行固定组数的 `_best_monotonic_partition`；只有
它无法运行时，才调用 legacy 全文锚点算法。legacy 路径依赖：

- 锚点最低余弦 `0.60`；
- trust-margin 斜率 `0.10` 和截距 `0.05`；
- 合并跨度上限 `20`、最小长度 `2`；
- 锚点密度预检 `0.20` 和最大锚点间隙 `50`；
- 容器上限 `10`；
- 锚点先切分搜索空间、最终 DP 只能在留下的候选中选择。

这些参数对全文旧算法各有历史理由，但没有理由继承到只有数行、且父对应已经成立的
局部条件问题。

在 `131703.report.json:39` 的真实文本上，原 `1:3` 关系可硬拆为 `7×3`，旧固定分区
边界为 `[3,4,7]`。把前两个真实组先合并并交换方向，得到与用户示例同形的真实语义
`3×2`：

```text
期望：2:1 + 1:1
DLD / posterior / raw composition / atomic：全部得到期望路径
状态：aligned
组合编码文本：5；结构候选边：4
```

legacy 在锚点阈值 `0.60` 时也得到正确路径；只把阈值改为 `0.80`，结果变成三条
`1:0` 加两条 `0:1`。而且 `align()` 的“完全没有锚点”分支直接生成全部孤行，绕过
`allow_deletions=False / allow_insertions=False`。当前 `try_split` 的集合覆盖检查仍会
通过，因为每个索引确实各自出现过。这个反例说明 legacy 回退不能严格实现局部无 gap
契约。

新原型仍依赖 hard splitter、embedding 模型和三个证据定义，但不再依赖上述七个
legacy 数值常量。它把不能接受的结构从候选空间移除，比“调低锚点阈值再检查结果”更
直接、可证明。

## 真实语料审计

扫描现有报告得到 174 个 `N:1 / 1:N` 关系：

- 40 例硬拆后仍只有一个片段，全部是原 `2:1 / 1:2`；它们应按“没有新增边界”拒绝，
  而不是按此前错误结论称为一般性的 `K<N` 不可解；
- 134 例确实产生了新边界，可进入局部递归对齐；
- 其中 133 例的局部问题最终输出 2 行，1 例输出 3 行；
- 条件均匀结构码没有改变这 134 例的复杂度，但在前述合成 `3×3` 中避免了错误的
  对角线偏好。

三视图门控的结果：

| 结果 | 数量 | 观察 |
| --- | ---: | --- |
| `aligned` | 115 | 自动路径全部与旧完整拼接分区一致，未观察到退化 |
| `needs_review` | 19 | 三种证据路径分歧，不自动覆盖父关系 |

对 19 个分歧逐案审阅：旧完整拼接分区在约 17 例中正确或更合理；DLD 在
`chapters-146059.report.json:289` 的一例看起来修正了旧边界；
`131707.report.json:372` 的真实边界落在硬拆片段内部，当前候选空间无法表达。
这说明：

- 完整拼接证据仍是现有局部语料上最强的单一基线；
- DLD 有独立信息价值，但尚不足以单独替代它；
- 三视图一致门控消除了已观察到的自动退化，代价是约 `19/134 = 14.2%` 的人工审阅；
- 这批关系来自旧算法结果，不是独立人工金标，不能把 `115/134` 当成准确率。

两个报告中实际保存过的 split（`167804.report.json` 的 `2×3` 和
`chapters-114222.report.json` 的 `2×2`）均由三种路径一致复现。自然语料里没有原生
`3×2` 的可审计 split，所以上述真实文本的合组/换向实验只证明表达能力和局部语义，
不等于新增一条独立自然金标。

## 性能与退化边界

134 个可拆关系在向量缓存全命中时：

- 局部求解总计约 `0.31 s`；
- 总候选边 `533`；
- 组合编码文本 `794`，本次均命中缓存。

迁移后又通过实际生产入口 `RepairService.try_split` 回放正式 `alignment` 目录中的
1,245 份报告：共发现 174 个 `N:1 / 1:N` 父关系，其中 40 个因 hard split 没有新增
边界而按契约返回 `unsplittable`，其余 134 个全部成功生成双边非空、等行数的局部
结果，无意外失败或 `needs_review`；缓存全命中总耗时约 `0.374 s`。这次回放验证了服务
适配、修复日志生成和结果展平，而不只是实验求解器。

独立随机矩阵尺寸实验（启用 `tracemalloc`，不含真实组合编码耗时）：

| 局部尺寸 | live 边 | 建边 | 求解 | 峰值内存 |
| ---: | ---: | ---: | ---: | ---: |
| `10×20` | 1,926 | 42 ms | 17 ms | 1.0 MiB |
| `20×20` | 5,906 | 123 ms | 78 ms | 3.17 MiB |
| `30×30` | 22,066 | 469 ms | 367 ms | 12.7 MiB |

候选边数量为 `O(nm(n+m))`；对每个组合边再编码完整块和 leave-one-out 变体时，编码
请求增长更快。典型局部窗口只有 2 至 10 行，所以当前实测远小于一次全文求解；但
`30×30` 已不应再被称为常数开销。若未来需要处理几十行的单个父关系，应把资源预算
作为显式运行限制并转人工审阅，或研究可证明的反事实候选闭包，不能引入语义阈值偷偷
删边。

## 已否定或修正的旧判断

已删除的早期固定分区原型 `experiments/local_split_mdl.py` 曾得出“`K<N` 必须拒绝”的
结论。这个结论只对“另一侧完全固定、必须输出 N 组”的旧问题成立，不适用于用户澄清
后的递归局部对齐。现在唯一的前置结构拒绝是“硬拆分没有引入任何新边界”。只要两侧
非空，完整无 gap 语法总有路径；例如 `3×2` 有两条复杂度均为 1 的路径。代码与专属
测试已经删除，错误问题定义及反证保留在本文中。

下列实验结论仍有效：

- 单纯用原子 mutual-rank 做固定分区，在 134 例中与完整拼接分区分歧 7 例（含并列），
  可判断案例中完整拼接更合理；
- 对重叠、长度不同的全部拼接跨度直接做 mutual rank，也没有得到更好结果；
- “完整块余弦比子块高”不是正确合并的充分条件，组合证据必须是软证据或分歧审计。

## 后续优化实验

### 严格上界的惰性组合编码

已删除的 `experiments/local_lazy_mdl.py` 曾保留完整候选图，但先给未编码组合边一个
可证明的最大证据：posterior 修正不超过 `log2(K)`，DLD necessity saving 不超过
`log2(K/H_K)`，归一化余弦不超过 1。每轮只编码当前最强的未知挑战路径；当最佳已编码
路径严格支配所有仍含未知边的路径时停止。

这个构造是精确 branch-and-bound，没有 beam width、分数阈值或结果近似。测试结果：

- 140 个确定性随机小矩形：DLD、posterior、raw 路径及 bit 均为 0 差异；组合文本只
  减少 2.4%；
- 134 个真实可拆关系：0 差异；组合文本从 794 降到 737，只减少 7.2%；260 条组合
  边仍需编码 242 条（93.1%）。

负面结论是：黑盒 embedding 的拼接向量在真正编码前几乎可以落到任何方向，DLD 的
安全上界天然较松。为了绝对无损，困难窗口仍须检查大多数边，而且多轮小批编码可能
增加远程调用延迟。当前收益不足以补偿实现复杂度，代码已删除；本节保留
“精确惰性搜索为何难以显著省编码”的实验结论。

### 按复杂度条件化的完整路径选择

更简单的分工是：

1. DLD 与 posterior 只选择需要多少合并结构，即复杂度；
2. 两者复杂度一致后，在该复杂度的全部完整路径中，以完整拼接余弦和选择边界；
3. 复杂度分歧或完整路径精确并列时 `needs_review`。

固定复杂度 `c` 的无 gap 路径都有 `(n+m-c)/2` 个关系，因此拼接余弦和不会因关系数
不同而获得额外项。这个分层方案不把余弦与 bit 相加，也不需要投票阈值。

真实 134 例中：DLD/posterior 复杂度分歧 0 例，raw 最优路径精确并列 0 例，因而
134/134 都可选择；边界全部回到既有完整拼接基线。结合此前人工审阅，这会保住约
17/19 个更合理的 raw 边界，但也会放弃 `chapters-146059.report.json:289` 那一个
DLD 看起来正确的修正，另一个候选空间不可表达的案例仍无法解决。

因此它是比“三视图路径必须完全相同”更简洁、更高自动化的候选，但现有证据只支持
“总体风险较低”，不支持“每例都优于 DLD”。原型函数
`select_path_conditioned_composition` 已显式统计最优路径数，绝不按遍历顺序吞掉精确
并列。

### 短文本的上下文条件化

原子 embedding 对完全相同或极短感叹词存在不可识别性。例如 `126203` 的两条源文
都是“啊。”，对 `Oh.` 和 `Ah.` 的原子矩阵两行完全相同：正确与错位对角和相等。
直接前后文的完整窗口把正确/错位对角和拉开为 `1.539 / 1.042`，但完整窗口会借用
邻文制造伪对应。

当时的隔离原型据此测试了反事实残差（实现未被采用，以下定义与结果作为实验档案保留）：

```text
v_context(i) = normalize(
    encode(previous + current + next)
    - encode(previous + next)
)
```

它不按字符数触发，对所有长度定义相同；直接前驱和后继是单调序列中最小的局部条件
集。真实 `Oh./Ah.` 岛上，完整窗口和残差都恢复正确对角。

在 20 个性能文档中按信息字符数选择最短的 80 个连续 `1:1` 银标中心行：

| 表示 | 三目标局部 top-1 | 保持邻文、把当前目标换成无关短句时选真值 |
| --- | ---: | ---: |
| 原子 | 80/80 | 76/80 |
| 完整上下文 | 78/80 | 51/80 |
| 上下文残差 | 80/80 | 73/80 |

完整上下文明确退化，不能作为普遍替代。残差没有破坏这 80 个局部检索，但在伪当前行
测试中仍略弱于原子证据，所以也不应无条件相加或覆盖。

另扫描全部章节得到 17 组“相邻两个生产 `1:1` 中恰有一侧文本完全重复、另一侧不同”
的可辨序列：原子分配 17/17 精确并列；完整上下文和残差都按生产顺序解开 17/17。
这些仍是生产结果银标，不是人工金标，但证明残差确实提供了原子表示中数学上不存在的
顺序信息。

当前最稳妥的短文本规则不是新增长度阈值，而是字典序破局：

```text
先按原子/组合主码选择；
只有主码的完整路径严格并列时，才惰性编码分歧岛的上下文残差；
残差仍并列则 needs_review。
```

这个规则不会推翻任何主证据的严格偏好，不需要给上下文乘权重，也只对实际不可识别岛
增加编码量。它能处理重复感叹词、相同省略号和重复表单字段的顺序歧义；对于 embedding
已经给出错误但非并列偏好的短句，它不会假装拥有纠错能力，后者仍属于校准或人工审阅
问题。

## 能力边界与下一步

以下情况不应通过新增阈值或例外修补：

- 真实边界位于 hard splitter 的某个片段内部；
- 一行只翻译了片段的一部分，或内容在两侧交错，需要一般 `N:M`；
- 局部存在真实漏译/增译，而当前操作承诺双边完整覆盖；
- embedding 无法区分短感叹词、专名、同主题译注或表单字段；
- 多条路径在现有语义表示下确实不可辨；
- 父关系本身就是错误对应；局部条件模型不重新证明文档级或父关系级存在性。

当前迁移已经明确 `needs_review` 的保留语义：GUI 标记“拆分需复核”，不静默回退
legacy，也不改写父关系。采用的分层门控在既有 134 个可拆关系上消除了早期三路径
全等门控的 14.2% 审阅率，但这些关系仍是旧报告银标，不应把 134/134 外推为人工金标
准确率。后续若取得独立局部金标，应优先校准证据模型，而不是恢复固定分区或 legacy
阈值。
